# Apply

`/apply <회사> <직무> [문항N] [final]`. 원자료 정리는 intake의 책임이고, 캘린더 등록 여부는 작성의 선행 조건이 아니다.

## 입력 준비

1. 선택한 직무의 공식 JD·분석·적합성, 실제 문항 원문·글자수를 확인한다. 로그인 뒤에만 보이는 문항은 사용자에게 그 문항만 요청한다. 비슷한 회사 문항을 대신 만들지 않는다.
2. 자격 `needs-review/ineligible`, 적합성 `재검토`이면 해결할 조건을 밝히고 해당 직무의 제출용 작성을 보류한다. 다른 직무나 검증된 경험 작업까지 중단하지 않는다.
3. `apply-packet.mjs catalog`의 검증 사실 요약으로 문항별 claim을 배정한다. 적은 문항은 메인이 evidence-matcher 역할을 수행하고, 대규모 문항 묶음만 Luna Max에 넘긴다.
4. `03_소재매핑.md`와 `application-request.json`을 [실행 계약](../../../docs/WORKFLOW_RUNTIME.md)의 apply 형식으로 만든다. 근거가 부족한 문항만 필요한 사용자 사실을 확인하거나 intake 갱신으로 돌린다.
5. `apply-packet.mjs prepare`로 배정된 claim·역할 제한·문항·JD만 포함한 입력 묶음을 만든다. `draft`만 새로 쓰고, `reuse-draft`는 형식 검사된 검수 전 초안, `reuse-final`은 현재 입력·본문에 대한 최종 PASS로 구분한다. 바뀐 입력이나 본문을 이전 PASS로 처리하지 않는다.

## 작성과 검수

- 메인이 Sol High 작성 역할을 수행하거나 draft-writer 한 번에 대상 문항을 묶어 맡긴다. 신입/경력 모두 실제 본인 역할·판단·결과가 드러나게 쓴다. 경력자는 담당 업무·프로젝트 책임·이직 목적 등 해당 문항이 요구하는 내용을 쓴다. 배정된 검증 claim에 없는 사실·수치·성과를 만들거나 준비·진행 상태를 완료로 높이지 않는다.
- `04_초안/`에 문항별 하나의 text 블록과 claim 추적표를 두고 `check-submission.mjs <파일> <제한>`과 `apply-packet.mjs checkpoint`를 실행한다. 사용자가 정확한 분량을 명시하지 않았다면 제한 이내로 쓰며 1000자 등을 억지로 채우지 않는다.
- 형식 검사를 통과한 본문은 `검수 전 초안`이라고 분명히 알려 바로 전달한다. 기본 작성에서는 fact-reviewer, revision-editor, 자동 재검수 루프를 호출하지 않는다. 초안 체크포인트는 PASS·`ready`·최종본이 아니다.
- 사용자의 일반 수정 요청은 요청한 문항·부분만 바꾸고 형식 검사와 checkpoint만 갱신한다. 새 사실이 필요한 부분은 그 부분만 질문하거나 제외하며, 다른 문항을 다시 쓰지 않는다.
- 사용자가 중간 사실 검수를 명시적으로 요청한 경우에만 작성자와 별개인 fact-reviewer(Sol High)를 호출한다. `record --stage fact` 기록은 선택 검수 이력일 뿐 최종 PASS가 아니다.
- humanizer-ko는 사용자가 명시적으로 요청했을 때만, 최종 검수 전에 적용한다. 문체 수정 뒤에는 형식 검사와 checkpoint를 갱신하며 기존 최종 PASS를 재사용하지 않는다.

## final

사용자가 내용 확정 뒤 `final` 또는 제출본 확정을 요청하면 공식 공고 상태/자격·문항 변경 여부를 확인한다. 변경 없으면 기존 분석·매핑을 재사용하며, 별도 중간 fact 검수를 선행 조건으로 추가하지 않는다. final-red-team-reviewer(Sol XHigh)는 작성 대화·이전 판정 없이 한 번 독립적으로 전체 현재 문항과 해당 근거를 읽어 사실·수치·역할·문항 충족·문항 간 일관성을 검수한다. 보고서에는 `검수 단계: final`, 입력 해시, 실제 검수 본문 해시를 남기고 `record --stage final`로 기록한다.

REVISE면 revision-editor가 지적된 문항만 별도 수정하고 새 주장·근거를 추가하지 않는다. 형식 검사 후 이전 지적과 변경 영향·문항 간 일관성을 한 번 재검수한다. 자동으로 무한 반복하지 말고 남은 문제가 있으면 사용자에게 보고한다. 모든 최종 파일이 현재 입력과 실제 본문 해시의 final PASS 범위에 속할 때만 민감정보 검사 후 `최종/`에 복사한다. `submitted`는 사용자가 실제 제출을 확인할 때만 기록한다.
