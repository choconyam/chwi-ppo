# Discover

사용자가 검색을 요청했거나 전체 흐름의 검색까지 맡긴 경우 실행한다. 검색 범위는 사용자 조건과 해당 기간의 공고 목록으로 정한다. 특정 회사 목록을 전수 순회하는 방식은 사용자가 회사군을 지정했을 때만 쓴다.

## 입력

`profile/PROFILE.md`의 지원 조건과 경험 요약부터 읽는다. 필요할 때 `node scripts/apply-packet.mjs catalog --out .work/discover/<run-id>/claims.md`로 검증 사실 요약을 만든다. 모든 원자료를 다시 읽지 않는다.

신입·경력·둘 다/미정, 선호 규모·직무·지역·입사 시점을 반영한다. 경력자는 JD가 요구하는 관련 경력과 고용형태를 비교한다. 누락된 조건은 모르는 상태로 검색을 계속하며, 최종 자격 판단에 필요한 질문만 묶어 확인한다.

## 후보 수집 → 기업별 JD 찾기

1. 자소설닷컴 등 채용 포털에서 후보 목록을 먼저 모은다. 자소설은 `node scripts/collect-jasoseol.mjs --out .work/discover/<run-id>/snapshot.json`으로 공개 목록을 읽는다. 완료 범위와 다음 페이지를 확인하고 부분 수집이면 `--resume`으로 이어간다. 수집기는 마감 제외 필터만 적용하므로 사용자 조건은 다음 단계에서 반영한다. 다른 포털이나 수집 실패 때는 웹 조회/브라우저를 사용한다. 세부 명령이 필요할 때만 [discover 실행 계약](../../../docs/runtime/DISCOVER.md)을 읽는다.
2. 적용한 필터, 확인 시각, 페이지/전체 건수, 실제 읽은 행과 URL을 snapshot에 남긴다. 첫 페이지만 읽고 전체 검색이라고 보고하지 않는다. 접근 실패는 채용 없음이 아니다. 같은 실패를 계속 재시도하지 않고 대체 목록 또는 검색 결과를 보충하되 누락 범위를 남긴다.
3. `scripts/discovery-plan.mjs`로 중복·확실한 조건 불일치만 제거한다. 공고 속 여러 직무는 분리하고, 세부 직무가 안 보이는 그룹 공채는 `inspect-roles` 대상으로 남긴다. 기업명이나 키워드 불일치만으로 탈락시키지 않는다.
4. 메인 또는 job-finder(Luna Max)가 생성된 queue.brief.md 기업 인덱스부터 읽고 관련되거나 모호한 기업의 연결 파일에서 세부 직무를 비교한다. 큰 queue.json 전체를 모델에 넘기지 않는다. 미리보기 밖 직무도 연결 파일에 보존되므로 표시 순위만으로 제외하지 않는다. 우선 후보와 미처리 큐를 함께 저장하고, 수집 단계에서 전수 JD 보고서를 작성하지 않는다.
5. 우선 기업의 공식 채용 목록에서 사용자에게 맞는 세부 JD를 찾는다. 포털에 잡힌 한 공고뿐 아니라 같은 회사의 다른 관련 신입/경력 공고도 확인한다. companyChecks는 현재 공고가 불일치해도 회사의 다른 공고를 확인할 대상이다. 같은 회사 공통 지원 조건은 한 번 읽고 여러 직무에 재사용한다. 학위·전공·졸업 시점·필수 경력 같은 공통 자격이 명백히 불충족이면 공식 요건과 한 줄 사유만 남기고 긴 `00~02` 보고서나 개인 경험 재비교를 만들지 않는다. 모호한 자격은 공식 확인을 계속한다.
6. 유망하거나 모호한 후보의 공식 확인과 JD 구조화만 필요에 따라 한 Luna Max 작업에 묶는다. 개인 프로필은 넘기지 않는다. 소량의 적합성 비교는 메인이 수행하고, 큰 후보 묶음만 role-fit-checker(Sol High)에 맡긴다. 자격 `eligible/ineligible/needs-review`와 적합성 `진행/주의/재검토`를 구분하고 공식 근거·사용 claim-id·부족 요건을 `02_직무적합성.md`에 남긴다.

## 빠르게 재실행

snapshot/큐가 있으면 이어서 처리하고, 같은 후보를 재검색하지 않는다. 공식 확인은 기본 24시간 이내 기록과 내용 지문이 같을 때 재사용한다. 조건 변경·마감 경과·변경 징후·지원서 최종 요청 때는 다시 확인한다. JD 내용이 같으면 분석도 재사용하고 프로필 변화는 적합도만 갱신한다.

서브에이전트는 큰 독립 묶음에만 기본 2개까지 사용하고 전체 대화 대신 입력 경로·작업 범위·출력 경로만 전달한다. 후보/직무마다 새 호출을 만들지 않는다.

## 결과

먼저 회사·직무·추천 이유·공식 마감·자격 확인사항을 한 표로 보여준다. 검색한 범위/페이지와 남은 후보 수를 함께 보고한다. 부분 수집·미처리 큐가 남으면 전체 탐색 완료라고 하지 않는다.

추천 결과를 저장하면 discover의 산출은 준비된다. 캘린더 반영을 기다리며 추천·작성을 늦추지 않는다. 사용자가 원하거나 track을 실행할 때만 `data/opportunities.json`에 병합·검증·동기화한다. 공식 미확인 마감은 확정 일정으로 표시하지 않는다.
