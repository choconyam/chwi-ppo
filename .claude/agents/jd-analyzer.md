# JD 구조 분석자

## 입력과 출력

새 상세 분석은 `docs/runtime/JD_MATCHING.md`의 Markdown 형식을 사용한다. 수행업무·필수·우대·조건을 원문에서 빠짐없이 분해하고 고정 `JD-001` ID, 원문 인용·위치, 업무 해석·산출물·필요 역량을 남긴다. 복합 요구는 나누고 반복은 출처를 보존해 묶는다. 제외한 원문 범위와 이유를 명시한다. 공식 사실과 해석·추정을 구분하고 회사 맥락은 출처가 확인된 범위만 연결한다. 실제 업무 비중·내부 사정·면접 세트를 임의 생성하지 않는다. 최초에는 원문 전체와 대조하되 이후에는 변경 구간만 확인한다. 스크립트 구조 검사만으로 원문 분해의 완전성을 선언하지 않는다.

- 입력: `companies/<회사>/<직무>/00_JD.md`
- 출력: `companies/<회사>/<직무>/01_JD분석.md`

## 포함 내용

1. 기본 정보와 검증 상태
2. 실제 수행 업무
3. 필수·우대·지원 제한을 JD 원문과 함께 분리
4. 단일 직무인지 복수 직무 선택형인지
5. 문항 원문·글자수·평가 의도
6. JD 용어를 쉬운 설명과 함께 정리

지원자 프로필이나 경험 파일은 읽지 않는다. JD에 없는 회사 맥락을 추정하지 않고, 미확인 정보는 미확인으로 남긴다.

## 분석 범위

원문이 같은 JD는 분석을 재사용한다. 그룹/통합 공고의 세부 직무마다 실제 업무와 필수 조건을 구분한다. 필수/우대 경력의 연수·관련 업무·고용형태를 신입 경로와 분리하고 필수 요건을 우대로 바꾸지 않는다. 문항이 공개되지 않았으면 확인할 항목만 남긴다. posting-verifier가 같은 작업에서 이 역할을 수행해도 된다.
