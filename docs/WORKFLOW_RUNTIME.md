# 워크플로 실행 계약 색인

사용자는 원자료 경로, 검색 조건, 선택한 직무를 자연어로 말하면 된다. Node.js 20.19 이상에서 추가 API 키·상시 서버 없이 동작한다. 모델은 해석·작성·필요한 검수를 맡고 스크립트는 변경·중복·형식·현재 입력 일치를 확인한다.

현재 작업에 해당하는 문서만 읽는다. 모든 워크플로가 이 색인이나 다른 단계의 세부 계약을 반복해서 읽을 필요는 없다.

| 작업 | 필요한 실행 계약 |
|---|---|
| 원자료 최초 정리·증분 갱신 | [intake](runtime/INTAKE.md) |
| 공고 목록 수집·공식 JD 검증·추천 | [discover](runtime/DISCOVER.md) |
| 지원서 소재 매핑·초안·선택 검수·제출 전 final | [apply](runtime/APPLY.md) |
| 공고 상태 조회·로컬 일정 동기화 | [track](runtime/TRACK.md) |

공통 원칙은 다음과 같다.

- 기본은 현재 메인이 직접 처리한다. 별도 위임 계획·판단 보고는 없으며 명백히 큰 독립 작업만 나눈다. 독립 검수는 사용자가 요청했을 때만 실행한다.
- compact packet·brief·인덱스를 먼저 읽는다. 이미 포함된 JD·claim을 확인하려고 원본 전체를 관례적으로 중복 읽지 않는다. 실제 불일치나 누락이 있을 때만 해당 원문을 추가 확인한다.
- 입력 지문·내용 해시·공식 확인 기록이 유효하면 완료 결과를 재사용한다. 확인 질문 하나나 형식 수정 때문에 전체 파이프라인을 다시 실행하지 않는다.
- 인간의 사실 확인, 공식 JD 확인, 개인정보 검사, 실제 제출 확인은 축소하거나 추정하지 않는다.

## 변경에 비례한 검증

- 설명·조회·읽기 전용 점검에는 전체 테스트나 산출물 재생성을 붙이지 않는다.
- 스킬·에이전트 문구 변경은 관련 분기·참조와 `check:skills`, `check:agents`로 동기화를 확인한다. README 오타만 고쳤다면 실행 테스트가 필요하지 않다.
- 한 실행 코드 변경은 영향받는 `scripts/tests/*.test.mjs` 또는 해당 기능 검사만 실행한다. 공통 데이터 계약이나 여러 단계 연결에 영향을 주는 변경은 `npm run test:workflow`를 실행한다.
- 설치·업데이트·대시보드까지 포함하는 전체 `npm test`는 해당 범위 변경이나 배포 전 통합 확인에 사용한다. 단순 지원서 편집에는 실행하지 않는다.

관련 실행/검사가 실패하면 이번 변경이 원인인 부분을 수정하고 영향받는 검사만 재실행한다. 실패나 추가 변경이 없으면 반복하지 않는다. 로컬 검증 완료는 실제 사이트 동작이나 모델 판단까지 검증했다는 뜻이 아니다. 실행 보고는 변경 결과·검증 결과·남은 보류를 중심으로 짧게 하고, 재개 위치·위임 횟수는 해당할 때만 남긴다. 측정하지 않은 시간·토큰 절감률은 쓰지 않는다.
